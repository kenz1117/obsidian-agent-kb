# Vault Specification

## Standard directories

```text
00-contract/      agent rules, glossary, decision index
01-inbox/         raw inbound material
02-sessions/      session records
03-knowledge/     distilled and canonical knowledge
04-projects/      project context
05-decisions/     decision records
06-sources/       original sources
07-maps/          indexes and dashboards
90-archive/       inactive material
assets/           attachments
```

## Lifecycle directories

```text
03-knowledge/auto/       generated by agents
03-knowledge/reviewed/   reviewed, not yet canonical
03-knowledge/canonical/  trusted, reusable knowledge
```

## Required frontmatter

All governed objects require:

```yaml
---
id:kb-20260101-example
type: knowledge
title: Example knowledge card
status: auto
source: source-id-or-path
confidence: medium
created: 2026-01-01
updated: 2026-01-01
tags:
  - example
---
```

## Types

| Type | Meaning |
|---|---|
| `message` | inbound agent message |
| `source` | original imported material |
| `knowledge` | distilled knowledge card |
| `session` | work session record |
| `decision` | decision record |
| `map` | index or dashboard |

## Status lifecycle

```text
pending → intake → auto → review → canonical → stale → archive → purge
```

## Canonical requirements

A card may move to `canonical` only when:

1. frontmatter is valid
2. source and provenance exist
3. no duplicate exists
4. no unresolved critical issue
5. confidence is `medium` or `high`
6. review policy allows automatic or manual approval
